# 柚影：GitHub 公开源调查与有限实测

> 本文保留首次调查记录；后续已接入七个公开源，并移除无尽/量子的旧失效接口。当前清单、媒体限制及升级说明见 [公共源第二轮扩充](08-public-sources-v2.md)。

## 结论

**找到了公开源，不必为了获得搜索接口继续逆向 Pineapple TV。**

其中一个候选在用户本机通过了搜索、详情和 HLS 清单请求。它使用的字段与柚影已有 JSON 适配器一致，可以作为手动配置候选。但“找到源”不等于“全部影片都能播放、下载”，本次没有做 Android 界面、实际解码或离线下载验收。

没有修改柚影业务代码，没有预置任何源，没有提交 Git，没有操作 MuMu 或修改 APK。

## 1. GitHub 项目

| 项目 | 实际用途 | 对柚影的意义 |
| --- | --- | --- |
| [vodtv/api](https://github.com/vodtv/api) | MoonTV/LunaTV 源配置集合 | 优先选择其中标准 HTTPS JSON/VOD 接口，逐个验证 |
| [LibreSpark/LibreTV](https://github.com/LibreSpark/LibreTV) | 公开播放器与接口兼容文档 | 其文档的 `ac=videolist&wd=`、`ac=detail&ids=` 与柚影现有请求形式一致；播放器项目本身不等于可用资源源 |
| [liu673cn/box](https://github.com/liu673cn/box) | TVBox 配置集合 | 配置含注释及 spider 入口，不能将订阅地址直接填作柚影 JSON/VOD API；本轮未执行第三方插件 |
| [iptv-org/iptv](https://github.com/iptv-org/iptv) | 公开直播 M3U 列表 | 主要是直播，不是影视点播搜索 API，不能直接解决当前选集与点播下载需求 |

实际读取的 [vodtv 精简配置](https://github.com/vodtv/api/blob/main/jin18.json) 有 **28 条**，其中 27 条 API 地址以 HTTPS 开头，4 条包含代理参数。未测试全部条目，也没有采用第三方代理。不能沿用仓库 README 声称的数量、成功率作为本次结果。

Pineapple APK 的静态字符串中也出现 `https://raw.liucn.cc/box/m.json`。这只是配置来源线索，不证明该应用此次实际使用了哪些条目。本轮按用户要求暂停进一步逆向。

## 2. 实测结果

测试时点：2026-10-14 02:51 UTC，以执行环境记录为准。

两处环境：Devin Windows VM、用户本机 Windows（认证 bridge 已恢复）。后者不是 Android/MuMu 网络环境。

测试关键词：`大闹天宫`。固定抽查三个源，各取一个搜索结果请求详情；仅检查少量 HLS 清单，不请求加密密钥、不下载影片、不批量采集。

| 源 | 用户本机搜索 | 用户本机详情 | 媒体检查 | 判断 |
| --- | --- | --- | --- | --- |
| 360资源 | HTTP 200，3 条结果 | HTTP 200，资源 ID 一致 | 主清单、子清单均 200；子清单含 AES-128 | 可作为搜索/详情接入候选；当前下载器不支持该样本 |
| 暴风资源 | HTTP 403 | 未继续 | 未继续 | 此环境不建议采用；未绕过拒绝访问 |
| 无尽资源 | HTTP 403 | 未继续 | 未继续 | 此环境不建议采用 |

补充：无尽资源在云端返回了搜索与详情，但其样本媒体清单发生 TLS 证书链校验失败。没有关闭证书验证。该差异说明云端可访问不能代替用户本机或 Android 可访问。

360 样本的 `vod_id` 为 `61455`，线路字段为 `360zy`，含 HTTPS M3U8。媒体子清单包含 2406 个 URI 引用，出现 `METHOD=AES-128` 与 `METHOD=NONE`。这不等于整个源都加密，也不应直接将 AES-128 等同 DRM；这里只确认当前下载器的限制适用于此样本。未请求 key 或媒体分片正文。

## 3. 在现有柚影中手动添加

打开 **设置 → 添加源**：

- 名称：`360资源`
- HTTPS JSON 接口：`https://360zyzz.com/api.php/provide/vod`

保存后，可用 `大闹天宫` 作为搜索验收关键词。本轮尚未在 App 中执行此操作，不能称为 UI 验收通过。

不要填写 GitHub 仓库页面、`jin18.json` 订阅地址或单集 `.m3u8`：现有“添加源”字段需要单个 VOD API，而不是订阅集合或媒体直链。

该接口的请求形式与现有实现一致：

```text
搜索：GET <API>?ac=videolist&wd=<关键词>
详情：GET <API>?ac=detail&ids=<vod_id>
播放列表字段：vod_play_from、vod_play_url
```

本次 JSON 结构核对不是 App 端解析器或播放器的端到端测试。

## 4. 能解决什么，不能解决什么

- **搜索和详情**：已找到用户本机可访问、字段匹配的真实接口，不再只有单集播放地址。
- **观看**：拿到播放地址与清单；仍须验证 Android 播放器解码、网络、音画和错误提示。
- **换源**：现有功能是同一条目内部换线路，不是跨站点自动合并同名影片。添加多个源并不自动实现跨站续播。
- **下载**：现有实现支持 MP4/WebM、受限的无加密 HLS 点播。此次加密样本不受支持；没有证明完整下载与离线观看成功。
- **稳定性**：这里只是单时点、单关键词的有限抽样，域名、证书、访问策略和节目可用性可能变化。
- **授权**：公开 GitHub 配置、HTTP 200 或接口自述均不构成内容版权授权。未验证这些第三方源的内容授权；正式分发或商用前需另行确认。

## 5. 下一步建议

优先对手动添加源后的“搜索 → 详情 → 选集 → 播放”做设备验收；用有权使用的无加密样本另验下载和离线播放。暂不为解决源地址问题投入更多 APK 逆向。

若后续要提高易用性，可独立增加：公开配置格式导入、源健康提示、跨源搜索结果关联、下载不支持原因提示。不要为了某个源取消 HTTPS 校验、绕过 403，或执行未知 TVBox 插件。

## 6. 复核材料

同一调查目录保存：

- `config-evidence.json`：配置来源、字节数、SHA-256、条目计数。
- `probe-cloud.json`：云端有限请求结果。
- `probe-user-windows.json`：用户本机有限请求结果。
- `probe_sources.py`：三个固定候选源的只读验证脚本。

证据保留状态码、结构、计数及媒体 host/path，不保存 Cookie、认证头、密钥或影片内容。脚本不进行搜索翻页或批量视频采集。
